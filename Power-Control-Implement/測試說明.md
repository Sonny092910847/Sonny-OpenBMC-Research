## 📝 詳細測試步驟

### 測試 1：Power On（開機）

**前置條件：** 主機必須處於 `off` 狀態

#### 步驟：

1. **檢查當前狀態**
   - 導航到：`http://localhost:8080/#/console/kvm`
   - 查看 Power Status 是否顯示為 `off` 或 `Off`
   - 應該會看到綠色的 **Power On** 按鈕

2. **開啟開發者工具（F12）**
   - 切換到 **Console** 分頁
   - 切換到 **Network** 分頁

3. **點擊 Power On 按鈕**
   ```
   點擊：[Power On] 按鈕
   ```

4. **觀察 Console 輸出**
   ```
   預期輸出：
   🔵 Power On 被點擊
   ```

5. **觀察 Network 分頁**
   - 應該會看到一個 API 請求：
   ```
   POST /redfish/v1/Systems/system/Actions/ComputerSystem.Reset
   ```
   - 點擊該請求，查看 **Payload**（請求內容）：
   ```json
   {
     "ResetType": "On"
   }
   ```

6. **觀察 Toast 通知**
   ```
   預期顯示：
   ✅ Power Control
   開機命令已發送
   ```

7. **觀察主機狀態變化**
   - 等待 5-10 秒
   - Power Status 應該會從 `off` 變成 `on` 或 `running`
   - Power On 按鈕應該會消失
   - Reboot 和 Shutdown 按鈕應該會出現

#### 成功判定：

- [ ] Console 有輸出 `🔵 Power On 被點擊`
- [ ] Network 有看到 POST 請求到 `/redfish/v1/Systems/system/Actions/ComputerSystem.Reset`
- [ ] Payload 包含 `"ResetType": "On"`
- [ ] 顯示綠色 Toast 通知「開機命令已發送」
- [ ] Power Status 從 `off` 變成 `on`

## 🔍 進階測試：監控後端通訊

### 方法 1：使用 curl 直接測試 API

**在 QEMU 外部（你的開發機器上）：**

```bash
# 測試 Power On
curl -k -X POST https://localhost:8443/redfish/v1/Systems/system/Actions/ComputerSystem.Reset \
  -H "Content-Type: application/json" \
  -H "X-Auth-Token: YOUR_TOKEN_HERE" \
  -d '{"ResetType": "On"}'

# 測試 Orderly Reboot
curl -k -X POST https://localhost:8443/redfish/v1/Systems/system/Actions/ComputerSystem.Reset \
  -H "Content-Type: application/json" \
  -H "X-Auth-Token: YOUR_TOKEN_HERE" \
  -d '{"ResetType": "GracefulRestart"}'
```

**如何取得 Token：**
1. 在瀏覽器開發者工具的 Console 中執行：
   ```javascript
   console.log(this.$store.getters['authentication/token'])
   ```
2. 複製輸出的 Token

---

### 方法 2：SSH 到 QEMU 監控 D-Bus

**SSH 連線到 QEMU：**

```bash
ssh -p 2222 root@localhost
```

**監控 phosphor-state-manager 日誌：**

```bash
# 方法 A：即時監控
journalctl -u xyz.openbmc_project.State.Host -f

# 方法 B：查看最近的日誌
journalctl -u xyz.openbmc_project.State.Host -n 50

# 方法 C：監控所有狀態管理器
journalctl -u xyz.openbmc_project.State.* -f
```

**監控 bmcweb 日誌：**

```bash
# 即時監控
journalctl -u bmcweb -f

# 過濾 Reset Action
journalctl -u bmcweb | grep -i "reset"
```

**使用 busctl 監控 D-Bus 訊號：**

```bash
# 監控主機狀態變化
busctl monitor xyz.openbmc_project.State.Host

# 查看當前主機狀態
busctl get-property xyz.openbmc_project.State.Host \
  /xyz/openbmc_project/state/host0 \
  xyz.openbmc_project.State.Host \
  CurrentHostState

# 查看請求的轉換
busctl get-property xyz.openbmc_project.State.Host \
  /xyz/openbmc_project/state/host0 \
  xyz.openbmc_project.State.Host \
  RequestedHostTransition
```

## ❌ 錯誤處理測試

### 測試錯誤情境

1. **測試網路錯誤**
   - 關閉 QEMU
   - 嘗試點擊 Power On
   - 預期：顯示紅色 Toast 通知，錯誤訊息

2. **測試認證過期**
   - 登入後等待 Token 過期
   - 嘗試執行操作
   - 預期：API 返回 401 Unauthorized

3. **測試操作進行中**
   - 點擊 Power On
   - 立即再次點擊其他按鈕
   - 預期：按鈕應該被禁用（disabled），顯示 spinner

## 🐛 常見問題排除

### 問題 1: 按鈕沒有出現

**可能原因：**
- 修改的檔案沒有正確複製
- 開發服務器沒有重新編譯

**解決方法：**
```bash
# 檢查檔案是否已修改
cat ~/webui-vue/src/views/Operations/Kvm/KvmConsole.vue | grep -i "power control"

# 重啟開發服務器
# Ctrl+C 停止
npm run serve
```

---

### 問題 2: 點擊按鈕沒反應

**可能原因：**
- Vuex Store 沒有正確導入
- API 端點不正確

**解決方法：**
1. 檢查 Console 是否有 JavaScript 錯誤
2. 檢查 Network 分頁是否有 API 請求
3. 檢查 QEMU 是否正在運行

---

### 問題 3: API 返回 404

**可能原因：**
- bmcweb 版本不支援該 API
- API 路徑錯誤

**解決方法：**
```bash
# 在 QEMU 中檢查 Redfish 版本
ssh -p 2222 root@localhost
curl -k https://localhost/redfish/v1/Systems/system
```

---

### 問題 4: Toast 通知是簡體中文

**原因：** 程式碼中寫死的是簡體中文

**解決方法：**
編輯 `KvmConsole.vue`，將所有中文訊息改成繁體中文或英文
