### 修改 6: Methods - 新增 Power Control 方法

**位置：** 第 285-439 行

**新增了 6 個方法：**

#### 6.1 `powerOn()` 方法

```javascript
async powerOn() {
  console.log('🔵 Power On 被點擊');
  try {
    await this.$store.dispatch('controls/serverPowerOn');
    this.$bvToast.toast('開機命令已發送', {
      title: '✅ Power Control',
      variant: 'success',
      autoHideDelay: 3000,
      solid: true,
    });
  } catch (error) {
    console.error('Power On 失敗:', error);
    this.$bvToast.toast(`開機失敗: ${error.message}`, {
      title: '❌ Error',
      variant: 'danger',
      autoHideDelay: 5000,
      solid: true,
    });
  }
}
```

**說明：**
- `async/await` 語法處理異步操作
- `this.$store.dispatch('controls/serverPowerOn')` 呼叫 Vuex action
- 成功時顯示綠色 Toast 通知（3 秒自動消失）
- 失敗時顯示紅色 Toast 通知（5 秒自動消失）
- `console.log` 用於除錯，可在瀏覽器 Console 看到

**資料流：**
```
powerOn() 方法
  ↓
this.$store.dispatch('controls/serverPowerOn')
  ↓
ControlStore.js 中的 serverPowerOn action
  ↓
HTTP POST /redfish/v1/Systems/system/Actions/ComputerSystem.Reset
  ↓
bmcweb 接收並處理
  ↓
D-Bus 呼叫 xyz.openbmc_project.State.Host
  ↓
phosphor-state-manager 執行開機
```

---

#### 6.2 `confirmReboot(type)` 方法

```javascript
confirmReboot(type) {
  const message =
    type === 'orderly'
      ? 'Are you sure you want to reboot the server gracefully? The operating system will be notified.'
      : 'Are you sure you want to force reboot the server immediately? This may cause data loss.';

  const title =
    type === 'orderly' ? 'Confirm Orderly Reboot' : 'Confirm Immediate Reboot';

  this.$bvModal
    .msgBoxConfirm(message, {
      title: title,
      okTitle: 'Confirm',
      okVariant: type === 'orderly' ? 'primary' : 'warning',
      cancelTitle: 'Cancel',
      centered: true,
    })
    .then((confirmed) => {
      if (confirmed) {
        this.rebootServer(type);
      }
    });
}
```

**說明：**
- 參數 `type` 可以是 `'orderly'` 或 `'immediate'`
- 根據類型顯示不同的確認訊息和標題
- 使用 `this.$bvModal.msgBoxConfirm()` 顯示確認對話框
- Orderly → 藍色 Confirm 按鈕
- Immediate → 黃色 Confirm 按鈕（警告色）
- 使用者點擊 Confirm 後才會呼叫 `rebootServer(type)`

#### 6.3 `rebootServer(type)` 方法

```javascript
async rebootServer(type) {
  console.log(`🔄 Reboot (${type}) 被點擊`);
  try {
    if (type === 'orderly') {
      await this.$store.dispatch('controls/serverSoftReboot');
      this.$bvToast.toast('優雅重啟命令已發送', {
        title: '✅ Power Control',
        variant: 'success',
        autoHideDelay: 3000,
        solid: true,
      });
    } else {
      await this.$store.dispatch('controls/serverHardReboot');
      this.$bvToast.toast('強制重啟命令已發送', {
        title: '✅ Power Control',
        variant: 'warning',
        autoHideDelay: 3000,
        solid: true,
      });
    }
  } catch (error) {
    console.error('Reboot 失敗:', error);
    this.$bvToast.toast(`重啟失敗: ${error.message}`, {
      title: '❌ Error',
      variant: 'danger',
      autoHideDelay: 5000,
      solid: true,
    });
  }
}
```

**說明：**
- Orderly → 呼叫 `serverSoftReboot` → ResetType: `"GracefulRestart"`
- Immediate → 呼叫 `serverHardReboot` → ResetType: `"ForceRestart"`
- Orderly 顯示綠色通知，Immediate 顯示黃色通知（警告）

## ⚠️ 注意事項

### 1. KVM 連線狀態 vs 電源狀態

**兩者是獨立的：**
- **KVM 連線狀態** (`isConnected`)：前端到後端的 WebSocket 連線
- **電源狀態** (`hostStatus`)：實際主機的電源狀態

**原本的限制：**
```vue
<b-button v-if="isConnected">  <!-- ❌ 原始版本 -->
```

**修改後：**
```vue
<b-button>  <!-- ✅ 無條件顯示 -->
```

---

### 2. 按鈕顯示邏輯

```
主機狀態 = off
  ↓
顯示 [Power On] 按鈕

主機狀態 = on/running
  ↓
顯示 [Reboot ▼] 和 [Shutdown ▼] 按鈕

主機狀態 = unknown
  ↓
不顯示任何 Power Control 按鈕
```

---

### 3. 操作進行中的處理

當 `isOperationInProgress = true` 時：
- ✅ 顯示 spinner
- ✅ 所有 Power Control 按鈕被禁用（`:disabled="true"`）
- ✅ 使用者無法同時執行多個操作

---

### 4. 錯誤處理

所有方法都使用 `try...catch` 捕獲錯誤：
```javascript
try {
  await this.$store.dispatch('controls/serverPowerOn');
  // 成功：顯示綠色通知
} catch (error) {
  console.error('Power On 失敗:', error);
  // 失敗：顯示紅色通知
}
```

## 🎯 設計決策說明

### 為什麼使用下拉選單？

**原因：**
1. 節省空間 - 不需要一次顯示 4 個按鈕
2. 分組邏輯 - Reboot 的兩種模式放在一起，Shutdown 的兩種模式放在一起
3. 視覺層次 - 主要操作（Reboot/Shutdown）在外層，細節（Orderly/Immediate）在內層
4. 與原始 Server Power Operations 頁面一致

---

### 為什麼需要確認對話框？

**原因：**
1. 防止誤操作 - Reboot 和 Shutdown 是破壞性操作
2. 提供資訊 - 讓使用者知道 Orderly 和 Immediate 的差異
3. 符合 UX 最佳實踐 - 破壞性操作應該要二次確認

**但 Power On 不需要確認：**
- Power On 不是破壞性操作
- 不會造成資料遺失
- 可以隨時關機

---

### 為什麼使用 Toast 通知？

**原因：**
1. 非阻塞式 - 不會打斷使用者操作
2. 自動消失 - 不需要手動關閉
3. 視覺回饋 - 讓使用者知道操作已經執行
4. 顏色編碼 - 綠色=成功，黃色=警告，紅色=錯誤
